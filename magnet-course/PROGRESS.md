# Progress

Status of all 35 classes. Updated in the same commit that completes a class,
never in a separate one, so the table and the git history cannot disagree.

The table below is generated by `tools/build_progress.py` from
`syllabus/magnet-bench-syllabus.html`. The id, number, unit, class title and
source columns are regenerated every run. The status, date, words and open
questions columns are read back and preserved, so edit those freely and rerun
the script whenever the syllabus changes.

Status values: `not started`, `sources verified`, `notes`, `draft`,
`worked code`, `artifact`, `done`.

## What the next session should pick up

Two things have to happen before class material starts, in this order.

First, run `python3 tools/verify_sources.py` from an environment that can reach
the open internet. That fills in `library/verified.log` and the `verification`
block in `library/sources.json`, and it is the precondition for everything else.
Then cache the free sources into `library/pdf/`, write
`library/notes/KEY.md` for each one actually read, and fill in the `contains`
line for each, which is the field that catches sources narrower than their
titles suggest.

Second, finish `shared/reference-part.md`. It currently holds the selection
criteria and the scoring rubric but names no candidate parts, because a
candidate needs a datasheet that was actually fetched. Every worked example in
all 35 classes uses this part, so it has to be settled before class 06.

After that, class 06 per `BUILD_PROMPTS.md`, which is the exemplar and the
hardest class in the course.
